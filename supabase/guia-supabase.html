🔐 Juegos de aula · multiusuario

Pasos para dejar funcionando la versión con usuarios y Supabase. Los tres primeros solo se hacen una vez.

1 Proyecto y registro en Supabase

  1. En supabase.com/dashboard, abre tu proyecto (o créalo con New project, región Europe).
  2. Authentication ▸ Sign In / Providers ▸ Email:
    • Enable Email provider: activado.
    • Confirm email: DESACTIVADO. La web usa correos internos que nadie recibe; si se queda activado, nadie podrá entrar tras registrarse.
    • Si aparece Minimum password length, ponlo en 8.
    Pulsa Save.
  3. En Authentication ▸ Sign In / Providers, arriba, deja activado Allow new users to sign up.

2 Crear las tablas y las reglas de seguridad

  1. Abre el archivo esquema-supabase.sql con el Bloc de notas y cópialo entero.
  2. En Supabase: SQL Editor ▸ New query, pega y pulsa Run.
  3. Debe decir Success. No rows returned. En Table Editor verás las tablas bancos y perfiles.
Si en el futuro te doy un esquema-supabase.sql nuevo, se ejecuta igual: no borra usuarios ni bancos.

3 Subir la web y crear el administrador

  1. Ejecuta desplegar-en-vercel.bat. Crea un proyecto de Vercel nuevo llamado juegos-de-aula-mu, así que la versión de siempre sigue intacta. Al final muestra la dirección que acaba en .app.
  2. Abre esa dirección, pulsa ✨ Registrarse y crea el usuario admin con tu contraseña.
  3. Vuelve a SQL Editor ▸ New query, pega esto y pulsa Run: 
    update public.perfiles set es_admin = true where usuario = 'admin';
    Dirá Success. No rows returned haya cambiado algo o no. Para comprobarlo de verdad: 
    select usuario, es_admin from public.perfiles;
    admin debe salir con es_admin = true.
  4. En la web, pulsa 👤 admin ▾ ▸ 🚪 Salir y vuelve a 🔑 Entrar. Verás la etiqueta ADMIN.
  5. Opcional: en ⬆ Gestionar Preguntas, el botón ⇪ Traer de la hoja antigua copia al banco general los bancos que tenías en la hoja de Google.
Sobre la contraseña del administrador: 86248624 estaba escrita dentro del código de la versión anterior, y ese código lo puede leer cualquiera que abra la web. Para admin usa una contraseña nueva. Si ya te registraste con esa, cámbiala en 👤 admin ▾ ▸ 🔑 Cambiar mi contraseña.

4 Qué queda protegido y cómo

QuéQuién puede verlo o tocarlo
ContraseñasNadie. Supabase las guarda cifradas (bcrypt). Ni el administrador ni la base las ven: el admin solo puede poner una nueva a quien la olvide.
Lista de usuariosSolo el administrador.
Bancos de un usuarioSu dueño y el administrador. Otro usuario o un visitante no los ve.
Enlace de juegoQuien tenga el enlace puede jugar ese banco concreto (no verlo en listas ni cambiarlo). Si un enlace llega a quien no debía, ⚙ Gestionar bancos ▸ 🔗 Nuevo enlace anula el anterior.
Banco generalLo ve cualquiera; solo lo cambia el administrador.

Esto no depende del código de la web, sino de las reglas de la base (Row Level Security): aunque alguien manipule la web desde su navegador, la base se niega. Lo he comprobado intentando saltármelas con un usuario normal.

La Publishable key que va en la web es pública a propósito: todas las webs con Supabase la llevan.
Nunca pongas en la web, ni compartas, la secret key / service_role ni la contraseña de la base de datos: esas sí se saltan todas las reglas.

5 Cosas que conviene saber

  • Pausa por inactividad: en el plan gratuito, Supabase pausa el proyecto si pasa ~1 semana sin uso. Para evitarlo, Vercel llama cada día a las 9:00 (hora de España en verano) a /api/despierta, que hace una consulta mínima. Puedes comprobarlo abriendo https://TU-WEB.vercel.app/api/despierta: debe decir "ok":true, y en Vercel se ve en Settings ▸ Cron Jobs. Si aun así se pausara, se reactiva desde el panel de Supabase (Restore project).
  • Sesión en los ordenadores de clase: por defecto la sesión se cierra al cerrar el navegador. Marca «Mantener la sesión abierta» solo en tu propio ordenador.
  • Contraseña olvidada: no hay correo de recuperación. El administrador pone una nueva en 👥 Usuarios ▸ 🔑 Contraseña.
  • La hoja de Google antigua: su Apps Script acepta cambios sin comprobar ninguna clave. Cuando hayas traído sus bancos y ya no uses la versión anterior, archiva esa implementación (Apps Script ▸ Implementar ▸ Gestionar implementaciones ▸ Archivar).
  • Tope: 200 bancos por usuario, para que nadie pueda llenar la base.
